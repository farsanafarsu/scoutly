Broken link checker

Broken link checker for 404 errors, redirect chains and dead ends

Broken links send visitors and crawlers to pages that no longer exist. Scoutly’s broken link checker crawls your site, tests the links it finds, and show exactly where each problem is: the page containing the link, the URL it points to, the response it got, and what to do about it.

Live

Link checks run in every website SEO audit: up to 120 internal and external links from up to 25 crawled pages. Broken links pointing to your site from other websites need backlink data, which isn’t available yet.

What it detects

The link problems worth fixing

Internal 404s and client errors

Links between your own pages that return 404 Not Found, 410 Gone or other 4xx responses.

Server errors

Links to pages that return 5xx errors, which can point to unstable pages or server problems rather than missing content.

Broken external links

Links to other websites that fail, including error responses, domains that no longer resolve, and requests that time out.

Redirect chains

Links that pass through several redirects before reaching the final page. Each hop adds delay for visitors and work for crawlers.

Redirect loops

Redirects that send a request back where it started, so the page never loads for anyone.

Weakly linked pages

Important pages with few internal links pointing to them, and orphaned pages that only appear in your sitemap.

What each result shows

Every broken link comes with its source and a next step

Knowing that a 404 exists is only half the job. You also need to know where the link is so you can fix it. When the data is available, each result shows:

  • Source page: the page that contains the link.
  • Destination URL: where the link points.
  • Detected status: the HTTP status code, redirect path or connection error.
  • Anchor text: the clickable text, so the link is easy to find on the page.
  • Recommended next step: update, redirect, restore or remove.

Some fields depend on what the server returns. A link that times out, for example, has no status code to report.

How to fix broken links

Four ways to repair a dead end

Update the link

If the content moved, point the link straight at the new URL. It’s the cleanest fix for internal links.

Add a redirect

If other sites or bookmarks use the old URL, a 301 redirect to the closest equivalent page keeps them working.

Restore the page

If the page was removed by mistake, or still gets visits and links, bringing it back may be the best option.

Remove the link

If there’s no good replacement, removing the link is better than sending people to an error page.

Redirects aren’t errors. A single 301 redirect is a normal way to move a page. Chains and loops are the problem: every extra hop slows visitors down, and crawlers may stop following a long chain before they reach the end.

Internal, external and inbound

Not all broken links are fixed the same way

Internal broken links are fully in your control and usually the most urgent, because they break your own navigation and waste crawl activity on pages that don’t exist.

External broken links point to other websites. You can’t fix the destination, but you can update the link to a working source or remove it.

Inbound broken links are links from other sites to URLs on your site that no longer work. Finding them needs backlink data. See the backlink checker.

FAQ

Broken link checker questions

Why does a link work in my browser but show as broken in a checker?

Some servers respond differently to automated requests. Firewalls, bot protection, rate limits, login walls and location restrictions can all block a checker while the page still loads for you. Re-test those links manually before changing them.

Is a 404 page bad for SEO?

A 404 is the correct response for a page that genuinely doesn’t exist, and Google has said 404s on invalid URLs don’t harm a site’s indexing or ranking. The problem is linking to them: visitors hit a dead end, and important content may be lost.

Should I fix broken links to other websites?

Yes, when you can. They don’t break your own pages, but they send visitors to dead ends and make content look out of date. Replace them with a working source or remove them.

What’s the difference between a 301 and a 302 redirect?

A 301 means the page moved permanently. A 302 means the move is temporary. Search engines treat a 301 as a strong signal that the new URL should be shown in results, so use it for permanent moves.

How often should I check for broken links?

After content changes, redesigns and migrations, and on a regular schedule. Sites that publish or remove pages often benefit from scheduled crawls.
